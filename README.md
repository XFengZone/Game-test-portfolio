## 🚀 代码实践项目

### 1. 并发登录压力测试与TCP握手分析 (Python / Requests / Wireshark)
- **场景**：模拟游戏开服或大版本更新时，大量玩家同时涌入登录的场景。
- **实现**：使用 `ThreadPoolExecutor` 多线程模拟100个用户同时发送 POST 登录请求，统计成功率和响应时间分布；对比多进程与多线程在 IO 密集型任务下的表现。
- **网络分析**：结合 Wireshark 抓包，分析并发请求下的 TCP 三次握手过程，验证连接建立的可靠性。
- **目录**：`/并发登录压力测试与TCP握手分析/concurrent-login-test/`

### 2. 接口测试基础脚本 (Python / Pytest / Requests)
- **场景**：日常接口回归测试。
- **实现**：掌握 GET/POST 请求发送、Cookie 关联处理（如登录态保持）、JSON 响应断言。
- **进阶**：结合 Pytest 编写测试用例，生成 Allure 测试报告。
- **目录**：`/api-test-basics/`

### 3. 游戏客户端设置项自动化验证 —— 帧率档位与音量设置 (Python / Airtest / OpenCV / PaddleOCR / WASAPI)

- **场景**：验证游戏内设置项是否**真正生效**。「点了按钮」不等于「设置起效了」，本模块通过自动化驱动设置后观测实际输出，验证「设置 → 实际表现」这条完整链路。游戏环境为《崩坏：星穹铁道》PC 端，1600×900 窗口化。
- **帧率档位验证**：截图裁剪帧率数字区域 → 按 **HSV 饱和度**过滤彩色数字（兼容达标时绿色、未达标时黄色的双配色，同时排除灰白标签）→ 放大 4 倍后 OCR 识别 → 10 次采样取中位数断言。设计上把采集与识别两阶段解耦，采样间隔由 0.65s 压缩至 **0.15s**；裁剪 + 放大后单次识别耗时从 11.16s 降至 **0.59s**，置信度 1.0。
- **音量设置验证**：通过 **WASAPI Loopback** 采集系统音频流（等价于 OBS「桌面音频」，不受环境噪声干扰）→ 切分 50ms 窗口计算 RMS → 取峰值窗口转 dBFS；采用**后台线程录音 + 主线程执行动作**保证发声落在采集窗口内。实测 `音量0=-160.0 / 音量5=-17.1 / 音量10=-11.9 dBFS`，动态范围 148.1 dB。
- **判定依据**：采用**跨档位相对关系断言**而非绝对阈值（动态范围 ≥25dB、音量0 ≤-55dBFS、响度单调递增）。因为不同场景 BGM 强度不同会使绝对电平漂移 5~8 dB，相对关系判据可跨场景、跨机器成立。阈值均为**倒推设定** —— 先确定目标缺陷会使数值变为多少，再将阈值置于正常值与故障值之间。
- **测试有效性验证**：两条用例均执行**红灯测试** —— 帧率用例人为将游戏设为 30 帧后运行 60 帧断言，确认其正确失败并打印全部采样点；音量用例临时调高阈值，确认断言能正确计算差值并报错。**一个从不失败的测试等于没有测试。**
- **进阶**：记录并定位了一个环境级缺陷 —— 三个 OpenCV 包共存导致 DLL 覆盖，使特征点匹配在原生层崩溃并穿透 `exists()` 掀翻整个测试；通过统一 `opencv-contrib-python==4.10.0.84` 修复，并将 `CVSTRATEGY` 收窄为纯模板匹配，最后用原始触发条件做回归验证。
- **目录**：`/hsr-client-automation-test/`
