# 🗂️ 游戏核心系统测试用例集

> 《原神》祈愿与元素反应、《崩坏：星穹铁道》差分宇宙 · 三套核心系统的用例设计与风险拆解

两个文件，回答两个不同的问题：

| 文件 | 回答的问题 | 使用场景 |
|---|---|---|
| `1_核心用例_30条.xlsx` | 这套用例**值不值得细看** | 快速评估，30 秒内看到信号 |
| `2_完整回归库_177条.xlsx` | 覆盖**有多全** | 看广度、查具体模块、做回归 |

## 💡 为什么分成两份

177 条完整、但也冗长。评审的时间有限，把 177 条平铺开，读者很难在十分钟内判断出「哪些是真有价值的」。

所以做了两层：

- **完整回归库**保留全部资产，作为可查、可扩展的底本
- **核心 30 条**按风险维度重新筛选，把「UI 显示检查」这类低信息量条目挡在外面

**30 条不是按编号截取的，也不是简单挑 P0。** 它是一次重新排序：原始库里 P0 占 66%，精选后 P0 占 30% —— 原来的优先级标记普遍虚高，精选时按「这个用例能发现什么级别的缺陷」重排了一遍。

## 📋 文件一：核心用例 30 条

单表结构，10 列：

| 列 | 说明 |
|---|---|
| 测试编号 | GC- / Elem_Reac_ / DU-AC- 前缀对应三大系统 |
| 测试标题 | 一行说清验证点 |
| 项目/模块 | 精确到子系统，如「原神·祈愿·保底机制」 |
| 优先级 | P0 9 条、P1 20 条、P2 1 条 |
| **用例类型** | 状态时序、数值、数据一致性、概率统计、功能、异常容错 |
| 前置条件 / 测试步骤 / 测试数据 / 预期结果 | 可直接执行的完整描述 |
| 实际结果 | 保留执行位 |

### 构成

| 来源 | 条数 | 说明 |
|---|---|---|
| 从 177 条库中提炼 | 26 | 含合并与改写，例如把「6 秒自动爆炸」与「5.9 秒不爆炸」合并为一条对偶边界用例 |
| 新增补充 | 4 | GC-062~065：三种货币为零的降级链起点、扣费后断网重连、重复提交幂等性、弱网下十连结果原子性 |

**这 4 条新增是刻意补的** —— 原库几乎没有网络层与幂等类覆盖，而祈愿是「扣费 + 发奖」的强一致场景，重复扣费与资源丢失恰恰是最该防住的缺陷。

### 六类风险与条数

| 用例类型 | 条数 | 典型问题 |
|---|---|---|
| 状态时序 | 9 | 上限、计时、顺序、冷却——「什么时候发生」 |
| 数值 | 6 | 倍率、取整、公式——「算得对不对」 |
| 数据一致性 | 5 | 回滚、显示与数据分离、保留策略——「两边说的是不是同一件事」 |
| 概率统计 | 4 | 保底、捕获明光、50% 判定——「多次之后分布对不对」 |
| 功能 | 3 | 背包边界、元素反应成立——「该发生的发生了吗」 |
| 异常容错 | 3 | 断网、零资源、弱网——「不正常时会怎样」 |

**被剔除的主要是这类**：「图标是否与原型一致」「界面文字是否正确」。它们不是不重要，而是**信息量低、可被截图评审替代**，放在回归库即可，不该占据核心位的篇幅。

## 🎯 怎么读

**只有五分钟**：看 `1_核心用例_30条.xlsx` 的「用例类型」列，能判断这套用例是按风险维度设计的，还是按界面元素罗列的。

**想验证覆盖度**：在 `2_完整回归库_177条.xlsx` 里按模块筛选，看某个子系统是否有对偶边界、是否有负向用例。

**想看真实项目产出**：翻后三张表 —— 缺陷报告的复现步骤完整度、回归结论的闭环方式、优化建议里的竞品参考与收益分析，这部分是最难伪造的。

---

## 🧠 筛选时用的四条判据

1. **有可推算的数值** —— 理论值能算出来、能和实测对上
2. **覆盖边界或对偶边界** —— 恰好在阈值上、恰好差一
3. **覆盖状态/时序/跨系统交互** —— 「视作」不等于实际、结算时机、计数重置
4. **覆盖异常与数据一致性** —— 失败回滚、重复提交、断线重连

满足两条以上才会进入核心 30 条；纯表现层的条目一律留在回归库。

## 🧱 已知局限

1. **这 177 条是设计产物，不是执行产物。** 逐条执行的证据在另一个项目——草原核溢出链专项，那里有 11 条用例的完整执行记录与判定。
2. 覆盖以 PC 端为主，移动端与手柄操作未单独成列。
3. 部分用例依赖特定账号状态（如背包武器数 1490、累计祈愿 89 次），复现需自备账号。
4. 数值类用例依赖游戏版本，版本更新后倍率与上限需复测。
5. 概率类用例的采样量在正文中标注，但单次执行难以达到统计显著性，需配合服务端数据或大样本验证。
