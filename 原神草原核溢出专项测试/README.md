## 一、测试方案

### 6 项待验证假设

| 编号 | 假设内容 | 两种可能的实现 |
|---|---|---|
| H1 | 溢出爆炸的伤害归属 | 按生成者属性 / 按触发者属性 |
| H2 | 溢出爆炸的发生位置 | 核的原始位置 / 第 6 颗的生成位置 |
| H3 | 连续溢出时的淘汰顺序 | 始终先进先出 / 首次溢出后失效 |
| H4 | 6 秒计时在切换界面时是否暂停 | 暂停 / 继续 |
| H5 | 多颗核同时触发时弹道是否全部命中 | 全部命中 / 可能丢失 |
| H6 | 溢出是否视同正常爆炸造成自伤 | 造成 / 不造成 |

### 范围与排除

- **覆盖**：溢出爆炸的伤害归属、发生位置、连续溢出的淘汰顺序、计时暂停语义、多核同时触发的弹道完整性、溢出是否造成自伤
- **排除**：元素附着量的计算。该项属反应系统底层参数，客户端无法观测，且不影响上述六项行为的判定

### 执行方法

- **环境固定**：帧率、画质、角色面板、目标怪物全程锁定；任一项变动都会让两次结果失去可比性
- **单变量**：一次实验只改一个条件，其余全部固定
- **重复取证**：同一操作至少执行三次；全程录屏，伤害数字逐帧读取
- **数据记录**：每条记录用例编号、环境摘要、本次变量、观测值、一致性、证据编号

## 二、测试用例

11 条，分三层组织：核心假设 6 条、交互优先级 1 条、交叉验证 4 条。

| 编号 | 验证目标 | 判定标准 |
|---|---|---|
| TC-01 | H1 伤害归属 | 与生成者单独爆炸差 ≤2% 判为生成者；与触发者差 ≤2% 判为触发者 |
| TC-02 | H2 爆炸位置 | 特效与伤害数字出现在 X 点判为原位；出现在 Y 点判为触发位 |
| TC-03 | H4 计时语义 | 切回后核已消失判为继续；仍存在判为暂停 |
| TC-04 | H5 弹道完整性 | 三次均出现 5 个伤害数字判为全中；少于 5 个判为丢失 |
| TC-05 | H6 是否自伤 | 掉血幅度与自然爆炸相当判为同等；不掉血判为特殊处理 |
| TC-06 | H3 淘汰顺序 | 依次引爆 1、2、3 号判为先进先出；仅首次生效判为状态缺陷 |
| TC-07 | 交互优先级 | 弹道飞行途中被溢出时，观察消失 / 继续 / 原地爆炸 |
| TC-08 | 交叉验证 | 精通相同、等级不同时，归属方向是否与 TC-01 一致 |
| TC-09 | 交叉验证 | 生成者离场后，伤害是否仍按其属性计算 |
| TC-10 | 交叉验证 | 护盾存在时，自伤是否先扣护盾 |
| TC-11 | 交叉验证 | 临界血量下，自伤是否可致死 |

**交叉验证的设计意图**：TC-08 排除等级混淆、TC-09 区分静态快照与动态取值、TC-10 与 TC-11 用可观测的护盾与死亡反推结算路径。

## 关键结论与玩家影响

| 结论 | 对玩家的意义 |
|---|---|
| 伤害按核创建者结算 | 无法用「低精通角色堆核、高精通角色触发」套利，溢出路径不存在练度空间 |
| 爆炸在原位置发生 | 「留核原地、引怪靠近、以溢出打伤害」这一操作成立 |
| 淘汰先进先出 | 可预判下一颗被引爆的是哪一颗，连续溢出可规划 |
| 菜单界面暂停计时 | 打开菜单时不会被残留的核炸伤 |
| 自伤等幅且可致死 | 低血量时会被自己生成的核炸死，需注意站位；护盾是有效防护 |
| 弹道目标死亡后失效 | 目标恰好死于弹道飞行途中时，该次伤害丢失 |

## 方法上的两个取舍

**一、为什么用假设驱动而不是「去测测看」**
每条用例都先写明两种可能的实现，再设计能区分它们的实验。这样实验结果是「落在哪一边」，而不是「看起来对不对」，判定不依赖主观感受。

**二、为什么做双向比对**
H1 只证明「与生成者一致」是不够的 —— 必须同时证明「与触发者不一致」，才能排除第三种算法。所以报告里两个百分比同时给出：0.0% 与 82.9%。

## 局限

1. 机制类行为可能随版本调整且不公告，结论需随版本复测
2. H1 仅使用一组精通差距最大的角色，若有角色特殊处理无法发现
3. 全部实验在固定帧率与画质下完成，低帧率下的表现未纳入
4. 结论基于客户端观测，服务端是否以相同规则结算不可观测
5. 伤害数字仅显示整数，四舍五入可能掩盖 1 点以内差异
6. 计时暂停仅在单人菜单界面验证，联机状态未覆盖
